3. Sua linha de montagem técnica (Passo a Passo)

Assim que o cliente fecha os 50% e manda as 6 respostas, esta é a sua sequência exata até o site oficial ir ao ar:

Etapa 1: Duplicar molde e ligar Cloudflare

Quem faz: Sandro (10 min)
Logo após fechar o cliente
  1. No GitHub, entre em Modelo_pasta-vertex → clique em Use this template → Create a new repository (nome sem espaços, ex: lp-clinica-vida, modo Private).
  2. No repo novo: Settings → Collaborators → Add people → convide o Mateus (para ele subir em entrega-design/).
  3. Na Cloudflare: Workers & Pages → Create application → Pages → Import an existing Git repository → escolha o repo novo → preset Astro → Save and Deploy.
  4. Clone o repositório novo na sua máquina (ou peça aqui para o Agente Principal clonar) e mande os links ao Mateus.

Etapa 2: Converter com os Agentes Duais

Quem faz: Sandro (Arquiteto → Construtor)
Quando o Mateus subir em entrega-design/

Lembrete da "Chave Liga/Desliga": enquanto o site estiver no link de teste (.pages.dev), a chave emProducao em src/config/site.ts começa como false — isso coloca uma "placa de Em Obras" para o Google não indexar o link provisório, mas libera o teste completo no celular e WhatsApp.

▸ Veja como fazer: puxar design + Prompt Oficial para o Agente Arquiteto
  1. Abra a pasta do projeto no Antigravity 2.0 (Arquiteto) e na IDE (Construtor) e puxe o que o Mateus subiu (git pull).
  2. Preencha os dados reais do cliente em src/config/site.ts.
  3. Cole o prompt abaixo para o Agente Arquiteto gerar a Ordem de Serviço (OS-XXX | PROMPT-XXX | ADR-XXX) e execute com o Agente Construtor na IDE.
  4. Ao finalizar o build e a purga, envie para o GitHub (git push) — em ~1 minuto a Cloudflare atualiza o link de teste.
Prompt oficial para colar no Agente Arquiteto:
Meu parceiro de design subiu o arquivo rascunho.html e as fotos dentro da pasta entrega-design/ para o cliente [NOME DO CLIENTE].

Inspecione o material em entrega-design/ e gere a Ordem de Serviço estruturada (OS-XXX | PROMPT-XXX | ADR-XXX) para o Agente Construtor executar no projeto Astro + Tailwind CSS preservando a identidade visual aprovada e aplicando nosso padrão completo de engenharia:

1. Estrutura de componentes e rotas: fatiar o rascunho.html em componentes limpos dentro de src/components/ respeitando a estrutura real do projeto (Landing Page, Site Institucional com seções de Quem Somos/Serviços/Equipe ou Cardápio Digital com categorias e itens), mantendo exatamente as fontes do Google Fonts declaradas no rascunho e montando as páginas em src/pages/.
2. Padrão de Mídia (web-media-standard): converter todas as imagens de entrega-design/ para .webp (máx. 1200px capa e 800px cards), salvar em public/images/, definir width/height explícitos para CLS=0, loading="lazy" abaixo da dobra, preload com fetchpriority="high" na imagem Hero e gerar o kit de favicons (WebP + PNG 48x48 + favicon.ico).
3. Captura e WhatsApp: conectar todos os CTAs ao src/config/site.ts e ligar o componente LeadWhatsAppForm.astro para redirecionar o cliente direto ao WhatsApp com os campos preenchidos (usando Formspree com honeypot apenas se configurado).
4. Auditoria Cirúrgica (surgical-eye-audit + mobile-web-first): validar alvos de toque mínimos de 48x48px, zero overflow horizontal em 360px-390px e contraste adequado.
5. Chave Geral de Produção, SEO Local e Arquivos de Infra:
   - Adicione em src/config/site.ts os campos emProducao (começando como false) e siteUrl (começando com a URL provisória .pages.dev).
   - Gere os arquivos robots.txt, sitemap.xml e llms.txt dinamicamente (src/pages/robots.txt.ts, sitemap.xml.ts e llms.txt.ts) lendo direto do site.ts: enquanto emProducao for false, bloqueie a indexação do Google (Disallow: / e meta noindex) sem bloquear o WhatsApp Preview (Open Graph); quando virar true, libere tudo com a URL oficial.
   - Preencha título, meta description, Open Graph e Schema.org (LocalBusiness em JSON-LD) no BaseLayout.astro, além de site.webmanifest e humans.txt em public/.
6. Purga Pré-Git (autonomous-deadcode-purger): após validar que tudo está funcionando em public/images/, purgar código morto, CSS zumbi, console.log e o rascunho.html/fotos brutas de entrega-design/ (preservando sempre entrega-design/LEIA-ME.txt, .agents/**, AGENTS.md, GEMINI.md e PROJECT_STATE.md).

Ao final, peça ao Construtor para rodar npm.cmd run build, confirmar Exit Code 0 e atualizar o PROJECT_STATE.md.

Quem faz: Você (e Mateus revisa)
